# 支付、账单与身份一致性

## 1. 为什么支付层权重这么高（20 分）

支付是全链路里**信息最密集、最容易被第三方核验**的一环。卡组织会返回发卡行、BIN 所属国家、卡类型；地址校验（AVS）会比对账单地址；3-D Secure 会留下验证结果；退款与拒付记录由银行保留。

这些数据的共同特点：**不是平台推断出来的，而是银行给的。** 所以支付层出现矛盾时，不存在"解释一下就能过去"的空间——矛盾就是矛盾。

反过来，支付层也是最容易守住的：用你自己名下、地址真实的卡，一次性把事情做对，之后基本不需要再管。

## 2. 四个一致性

| 一致性 | 怎么看 | 不一致的后果 |
| --- | --- | --- |
| 卡 BIN 国家 = 账单地址国家 | 银行 App 的卡信息 + 账单地址 | 最典型的"支付信息可疑"信号 |
| 账单地址国家 = 接入 IP 国家 | 对照你日常网络所在地 | 需要解释；若无材料，风险持续存在 |
| 注册姓名 = 持卡人姓名 | 账号资料 vs 卡面 | 需要 A 级材料（亲属关系、企业授权） |
| 支付主体 = 实际使用者 | 谁付钱、谁在用 | 共享/代付的结构性风险 |

**双币卡/境外卡不算问题**：卡的发行国与你的居住国不同是正常的（比如在 A 国工作、用 B 国卡）。真正的问题是**这些信息彼此矛盾且无材料解释**。

## 3. 卡与支付方式

| 方式 | 合规性 | 主要风险 |
| --- | --- | --- |
| 本人名下的一手信用卡/借记卡，账单地址真实 | 推荐 | 无明显风险 |
| 家人名下的卡（本人同意、可出具关系说明） | 可用但需解释 | 姓名不一致，需要 A 级材料 |
| 公司卡 / 企业采购 | 推荐（团队场景） | 需确认合同主体与使用者一致 |
| 虚拟卡 / 预付卡 / 礼品卡余额 | 不要用 | 无法核验持卡人；常与批量注册绑定 |
| 代付 / 代充 / 合租分摊 | 不要用 | 支付主体与使用主体分离，等于把账号交给别人 |
| 多人共卡（一个卡付多个账号） | 不要用 | 账号天然关联，一损俱损 |

**关于"虚拟卡只是支付工具，没那么严重"**：在风控视角里，虚拟卡的价值就是"不绑定真实身份"。使用它等于主动放弃"支付层可核验"这个最强的自证手段。你省下的可能是几美元手续费，付出的是申诉时唯一有力的证据。

## 4. 退款与争议（最危险的一项）

拒付/争议（chargeback、dispute、"未授权交易"）是支付体系里最严重的标记之一：

- 它由银行发起，平台必须响应，过程留痕；
- 它意味着"这笔支付被认定为可疑或非授权"，直接冲击账号的支付可信度；
- 它通常与"账号被盗用/被转卖"高度相关。

**合规做法**：

1. 想退款 → 走平台的正规退款渠道，不要先找银行发起争议。
2. 已经发起争议 → 主动与平台沟通、撤销争议、补齐支付；不要隐瞒。
3. 永远不要"用完服务再争议退款"——这不是省钱技巧，是支付欺诈。
4. 如果卡被盗刷导致你发起争议 → 保留银行立案材料，这属于可解释情形（A 级）。

## 5. 身份一致性

- 注册姓名用**真实姓名或稳定的企业名称**，不要用昵称、拼音缩写、临时邮箱人格。
- 企业场景：注册主体 = 合同主体 = 发票主体 = 实际使用者所在组织。
- 需要提交身份材料时，用真实材料；**伪造材料的后果远大于账号被封**。
- 姓名变更（婚姻、改名）保留变更证明，避免以后解释不清。

## 6. 团队与企业的合规花钱方式

| 需求 | 不要这样做 | 应该这样做 |
| --- | --- | --- |
| 5 个人要用 | 一个账号共享，或买 5 个个人号 | Team 版席位，按人授权 |
| 要开发票 | 用别人的公司抬头 | 用自己公司的采购流程，主体一致 |
| 要控成本 | 找代充/低价中转 | 评估用量、走年付/企业折扣，或换更便宜的合规模型 |
| 要给外包用 | 把主账号密码给外包 | 单独席位 + 到期回收；或让外包用自己的账号 |
| 要离职交接 | 密码转交 | 组织管理员移除成员、吊销其 Key |

## 7. 自查步骤（10 分钟）

1. 打开银行 App，记录：卡类型、BIN 前 6 位的国家、账单地址国家。
2. 打开账号的账单/订阅页，核对：姓名、地址、支付方式末四位。
3. 用 `curl -s https://ifconfig.me` 记录日常接入 IP 的国家。
4. 把三项写在一张纸上：**BIN 国家 / 账单国家 / 接入国家**。三者不一致就列入待办。
5. 查近 24 个月银行账单里有无 "dispute/chargeback/争议" 字样。
6. 确认这张卡还绑定了哪些账号（自己的、家人的、公司的）——共卡就是关联。
7. 把所有材料（账单、发票、订阅确认邮件）存进一个加密目录，命名为 `account-evidence/`。

## 8. 证据强度

| 材料 | 级别 | 备注 |
| --- | --- | --- |
| 银行对账单（可遮盖卡号，保留姓名/地址/日期） | A | 申诉主力材料 |
| 平台发票 / 订阅收据（含订单号） | A | 证明支付关系 |
| 公司采购合同 + 发票 | A | 企业场景必备 |
| 支付成功邮件截图 | B | 佐证时间线 |
| 银行出具的争议撤销确认 | A | 解释历史争议 |
| "这卡是我的" | C | 姓名对不上时无效 |

## 9. 自查清单

- [ ] 我用的卡是本人名下的一手卡，账单地址是真实地址
- [ ] 卡 BIN 国家、账单国家、日常接入国家三者一致（或有材料解释）
- [ ] 注册姓名与持卡人姓名一致（或有关系说明）
- [ ] 近 24 个月没有争议退款/拒付记录
- [ ] 这张卡没有同时给多个账号付款
- [ ] 团队场景走的是席位/企业采购，不是共用一个号
- [ ] 我把账单、发票、订阅邮件存进了一个加密目录

## 10. 不要做的事

- 不要用虚拟卡/预付卡/礼品卡余额"对齐"账单国家。
- 不要用他人的卡、代付、代充来"解决支付问题"。
- 不要为了退款先发起银行争议。
- 不要在多账号之间轮流用同一张卡来"分摊风险"——这是把风险连成网。
- 不要伪造账单地址、姓名或身份材料。这不是"配置问题"，是欺诈。
