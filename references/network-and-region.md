# 地区、网络与设备一致性

## 1. 你要守住的是"一致性"，不是"看起来像"

平台判断网络层风险的方式，本质上是问三个问题：

1. 这个人申报的地区，和他实际接入的地区是不是同一个？
2. 他今天接入的方式，和他上个月接入的方式是不是同一类？
3. 这个出口上，是不是还有很多别的人在同时用？

**这三个问题只能用真实情况回答。** 你无法通过技术手段把"不在支持地区"变成"在支持地区"——那只是让第 1 个问题从"矛盾"变成"矛盾 + 欺诈"。所以本文件的全部目标是：让你的真实情况**没有矛盾**，而不是伪装出没有矛盾。

> 如果你人在支持地区名单之外：唯一合规的做法是走 `third-party-risk.md` 第 6 节的合规替代路径（本地合法可用的模型、云厂商在支持区域的通道、或企业采购）。不要试图"接进去"。

## 2. 一致性三角

```
        注册地区
        /      \
       /        \
   接入地区 —— 支付地区
```

- 三个角都指向同一个国家/地区：这是最稳的状态。
- 一个角不一致：通常可以用 A 级材料解释（跨境办公、留学、搬家、公司总部在另一国）。
- 两个角以上不一致，且无法用文件解释：这就是"身份一致性存疑"，申诉时很难说服任何人。

**常见正当情形**（都建议提前备好材料）：

| 情形 | 会出现的矛盾 | 建议准备的材料 |
| --- | --- | --- |
| 跨境远程办公 | 接入地 ≠ 注册地/支付地 | 公司出具的远程办公说明、工位/租房合同、出入境记录 |
| 留学生 | 支付地（家里付）≠ 接入地 | 学生证/在读证明、亲属关系说明、学费缴款凭证 |
| 公司总部在 A 国、员工在 B 国 | 支付地 A、接入地 B | 劳动合同、公司注册证明、发票主体说明 |
| 短期出差 | 短时间内跨洲 | 机票/酒店订单、会议邀请函 |

这些材料的共同点：**第三方出具、可核验、时间线清楚**。这是 A 级证据；口头解释是 C 级。

## 3. IP 类型

| 类型 | 常见来源 | 特征 | 自查提示 |
| --- | --- | --- | --- |
| 住宅宽带 | 家庭/宿舍 | 与你真实居住地绑定，最自然 | 最不需要解释的类型 |
| 企业专线 | 公司办公室 | 出口固定，可能多人共用 | 找 IT 确认出口与共用范围 |
| 移动网络 | 4G/5G | 出口会随基站变化 | 变化是正常的，不用刻意固定 |
| 数据中心 | 云主机、VPS、CI | 与"住宅"画像差异大 | 不要把"日常使用"跑在云主机上 |
| 代理/中转出口 | 商业代理、共享池 | 大量用户共用，历史行为混杂 | 这是风险源，不是解决方案 |

**"类型混用"为什么是信号**：一个人的真实生活通常只覆盖 1–2 类（家里 + 公司，或家里 + 手机热点）。如果同一个账号在一天内既走住宅宽带、又走数据中心、又走商业代理，这个"人"的行为画像就崩了。

**企业出口的邻居风险**：如果你和几百人共用一个 NAT 出口，而这个出口上有人在做违反条款的事，你的账号会跟着承担"同一出口异常行为"的关联风险。这不是你能控制的，但你可以：① 让 IT 说明出口边界；② 把关键业务迁到云厂商通道；③ 在申诉材料里保留"该出口为公司统一出口"的证明。

## 4. 设备与时区

平台能看到的"设备"信息包括：浏览器/客户端标识、Cookie 与本地存储、屏幕与时区设置、语言偏好。它们的作用不是"认出你是谁"，而是判断"这些是否属于同一个稳定环境"。

自查要点：

- **时区/语言与所在地**：系统时区、`TZ` 环境变量、`LANG`/`LC_ALL` 是否与你的实际所在地一致？在 `audit.py` 里用 `--declared-region` 可以得到一个"仅提示"的检查。
- **设备数量**：账号设置里通常能看到登录设备/会话列表。出现陌生城市就是凭据泄露的信号，不是"平台乱来"。
- **环境切换**：频繁重装系统、换浏览器、清 Cookie、开无痕模式，会让"设备画像"反复重建。没有必要就别折腾。
- **虚拟环境**：虚拟机、容器里跑桌面客户端、云桌面登录网页版——这些在设备层就是"数据中心设备"，与住宅场景不符。

## 5. 自查命令（只读，不联网上传）

```bash
# 1) 当前出口 IP 与归属（用任意公开回显服务，注意不要用来源不明的服务）
curl -s https://ifconfig.me

# 2) 时区与语言
echo "$TZ / $LANG / $LC_ALL"
date

# 3) 项目里有没有 base_url / proxy 指向第三方
python scripts/audit.py --path . --declared-region <你的地区> --no-history

# 4) 环境里的代理变量
env | grep -iE 'proxy' | sed 's/=.*$/=<REDACTED>/'
```

第 4 条注意：**不要**把 `env` 的完整输出贴到任何地方（可能含密钥）；先脱敏再分享：

```bash
env | python scripts/redact.py > env.redacted.txt
```

## 6. 处置动作（按顺序）

1. **确认合规性**：你的所在地是否在 <https://www.anthropic.com/supported-countries> 名单内。不在 → 直接看 `third-party-risk.md` 第 6 节。
2. **固定接入方式**：选一个你真实的主要网络（家里或公司），不要在同一账号上混用多种网络类型。
3. **清理"为了改 IP"而存在的组件**：代理链、住宅代理、IP 轮换脚本、指纹浏览器、多开工具。它们的存在本身就是风险证据。
4. **确认企业出口**：向 IT 要一份出口说明（出口 IP 段、共用范围、是否有其他 SaaS 账号共用）。
5. **记录真实环境**：出口 IP、运营商、所在地、常用设备清单。写进你的"账号档案"，出事时直接用。
6. **重新跑一次评分卡**：N1–N5 应该降到 0 或最多 1 项。

## 7. 证据强度对照

| 材料 | 级别 | 说明 |
| --- | --- | --- |
| 公司 IT 出具的出口说明（盖章/工单号） | A | 说明"该 IP 是公司统一出口" |
| 云厂商资源所在地的账单 | A | 说明云主机在哪个区域 |
| 路由器/防火墙 NAT 日志导出 | B | 需脱敏后引用 |
| 机票/酒店订单 | A | 解释跨洲跳变 |
| 自己截图"设备列表" | B | 用于自查，申诉时作为佐证 |
| "我一直在家用" | C | 无日志时不可用 |

## 8. 自查清单

- [ ] 我确认自己所在地在支持地区名单内（或已改走 `third-party-risk.md` 第 6 节的替代路径）
- [ ] 我的接入 IP 与注册地、支付地一致，或有一致性材料可解释
- [ ] 我的账号只在一种类型的网络下长期使用
- [ ] 我知道企业出口是否被他人共用，并保留了一份出口说明
- [ ] 我的系统时区/语言与所在地一致
- [ ] 我没有为了"改地区"而使用代理、轮换节点或指纹浏览器

## 9. 不要做的事（违反条款，且是被封的首要原因）

- 不要采购/使用住宅代理、轮换 IP、机场节点来"修正"地区。
- 不要用指纹浏览器、设备伪装、改 UA 来"模拟"另一个环境。
- 不要为了"分散风险"在多地区同时登录同一账号。
- 不要相信"某个节点更安全"这类说法：**节点本身就是矛盾的制造者**。
